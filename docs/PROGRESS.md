設計經過一輪 LLM 檢視後定案，關鍵決策：
  1. **計分改為乘法結構**（非四因子等權加總）：`最終分數 = 籌碼分數 × 技術就緒係數`。籌碼是主因、技術面只放大或抑制它、不能取代——避免「零籌碼但盤整量縮」的股票靠 c/d 兩項就衝進前排。
  2. **籌碼分數 = 投信分數 × 0.7 + 其他法人分數 × 0.3**。投信分數：近 20 日「買超頻率」（淨買超天數佔比，取代脆弱的連續買超天數——投信實務常穿插一天小賣超，嚴格連續會歸零）＋「買超淨額佔發行量比例」（帶正負號），兩子項各半權重、各自 `rankScore`。其他法人分數：**排除投信**，只算 `sum(外資+自營商淨買超) ÷ sum(volume)`（帶正負號、視窗加總而非逐日比例平均）——排除投信是為了從結構上消除與投信分數的雙重計數，不用事後正交化。
  3. **技術就緒係數**：`壓縮度 × 0.5 + 窒息量 × 0.5`（0~100）線性映射到 `READINESS_FLOOR`(=0.5)~1.0。下限 0.5 刻意設計：技術面完全沒收斂只把籌碼分數打對折、不歸零、不從排名抹掉（連續係數取代 cliff 式剔除，符合「不用硬門檻」原則）。壓縮度分數直接沿用 `breakout-shared.ts` 的 `computeBase`（帶寬歷史百分位＋低帶寬持續天數），與突破腳本口徑一致；窒息量用近 5 日 `volume/volumeMa20` 平均量比（多日平均濾單日雜訊）。
  4. **候選池資格篩選**（pool eligibility，非訊號門檻）：剔除「今日 close > 布林上軌」（與 `calculate-breakout-strength.ts` 觸發條件互斥，兩份清單天生不重疊）與「近 20 日均量 < `MIN_AVG_VOLUME_SHARES`(=500 張)」（避免長期無量的死股因「量/均量」比值天生不穩而系統性霸榜）。`sharesOutstanding` 為 null 不剔除，只讓投信分數的佔比子項降級。

所有待校準參數（`CHIP_WEIGHTS`/`TRUST_SUB_WEIGHTS`/`TECH_WEIGHTS`/`READINESS_FLOOR`/`MIN_AVG_VOLUME_SHARES` 等）集中在 `accumulation-shared.ts`。結果不寫資料庫，輸出至 `data/accumulation-score-results/{date}.json`，`code`+`date` 欄位格式對齊突破腳本輸出——方便日後寫比對腳本驗證「冷水區 top-N 之後 N 天內有幾支真的出現在突破結果裡」的預測力。
